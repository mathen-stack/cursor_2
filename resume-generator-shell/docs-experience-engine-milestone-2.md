# Experience Engine Milestone 2

Milestone 2 replaces only the fixed mock Requirement Extractor with a real,
evidence-grounded JD Requirement Extraction Engine. Every downstream component
(role assignment, bullet planning, keyword allocation, STAR generation, bullet
composition, and validation) remains mocked so this milestone stays isolated.

## Implemented

- Provider-neutral `StructuredLanguageModel` interface
- `RealRequirementExtractor` with context and JD-hash verification
- Offline `RuleBasedRequirementModel` for deterministic local development
- Strict runtime validation of structured model output
- Atomic splitting of compound actions such as build, deploy, and monitor
- Required, preferred, and implied necessity classification
- Expanded requirement categories and priority levels
- Exact source evidence with character offsets
- Known-technology hallucination rejection
- Lexical grounding validation for normalized requirements
- Conservative semantic duplicate merging
- Deterministic `REQ-001` style IDs assigned after validation
- Concurrent-run isolation and input immutability coverage
- Milestone 2 Experience Engine composition root

## Public composition root

```ts
import { createMilestone2ExperienceEngine } from "@resume/engines";

const engine = createMilestone2ExperienceEngine();
const result = await engine.execute(input);
```

The built-in rule-based model reads the actual JD and does not return fixed
resume content. A future OpenAI, OpenRouter, Anthropic, or other provider adapter
can implement `StructuredLanguageModel` and be injected into
`RealRequirementExtractor` without changing the engine.

## Validation boundary

Each accepted requirement contains:

- stable requirement ID
- exact JD source text
- one atomic normalized requirement
- category
- priority
- necessity
- one or more exact evidence ranges

No roles, supporting keywords, action verbs, STAR stories, metrics, or resume
bullets are generated by this extractor.
